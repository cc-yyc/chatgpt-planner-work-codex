## 规划覆盖缺口

案例2未单列以下两项验证。它们属于用户最初 CSV 验收要求，因此这份规划不能直接作为完整验收清单：

- 断网条件下实际完成导出，确认导出流程不依赖网络。
- 比较导出前后完整原记录的数量与内容，确认没有修改。回答仅在取消和失败状态中局部提到不修改账目。

以上是对本次生成回答的覆盖观察，不能据此断言技能在所有请求下都会遗漏；本轮没有修复或改写技能。

## 实际本地验证

案例4使用全新目录，仅产生 message.txt：

- 初始写入并实际回读：hello plannner（14 字节）。
- 修正内容：hello planner。
- 另一条只读命令独立读取最终字节：hello planner（13 字节），无 BOM、无回车、无换行。
- 最终十六进制：68656c6c6f20706c616e6e6572。
- 最终 SHA-256：330c569e0a07d0909765eccb3babdd5ea71bd49c406eb5f16b00cb75c0ab146c。
- 目录检查结果仅包含 message.txt，没有覆盖既有文件。

首次普通沙箱写入报告和测试目录均返回拒绝访问。已记录这些失败；随后在原先获准的精确目录内通过受控执行完成，没有扩大文件范围。最终文件验证是实际完成的检查。

实际执行方式为 PowerShell 单引号 here-string 将脚本传给 python -X utf8 -。保存的脚本及工具输出可用于审阅实际操作；创建脚本在目录已存在时会拒绝重跑，避免覆盖证据。

案例3从返回答复提取 JSON，调用 jsonschema.Draft202012Validator 检查已安装 Schema，退出码 0、错误数 0、字段数 6、验证项 4。此项只证明结构有效；业务覆盖由人工逐项复审，不能由 Schema 证明。

## 未验证范围

- 没有实际进入 ChatGPT 普通 Chat 或 Work 加载技能，也没有验证自动技能选择、UI 列表刷新。
- 没有创建聊天、真实派发、回传或跨端复审；相应结果仅是情境行为检查。
- 没有记账工具仓库，未实现或验证真实 CSV 导出，未生成业务 CSV 样例。最初全部功能验收仍不能给 PASS。
