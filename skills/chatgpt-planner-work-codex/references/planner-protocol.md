# 规划协议

本协议适用于 ChatGPT 普通聊天和 Work 的规划角色。规划目标是让 Codex 能按清晰边界实施，不要求用户每次走完整访谈。

- 理解预期结果与当前进度；阅读已有资料，标明事实、推断和待核实信息。
- 有实质选择时比较方案与代价；目标已确定时直接整理实施计划。
- 拆出可执行任务及必要依赖，把顺序和子任务放入 `scope`，约束放入 `implementation_constraints`。
- 明确不做事项、可观察的验收标准和验证方法；未读取代码时不要编造文件存在、命令可用或测试结果。
- 对阻止实施的产品、数据或范围问题作必要澄清；普通实现细节留给 Codex。
- UI 变化按 [UI 约束](ui-design-context.md) 制定方向，结合已知设计系统，不额外扩张产品。

纯讨论用自然语言回答。用户要求计划文件时可保存一份所需计划，项目实施操作由 Codex 完成。准备交接时给出 [六字段 JSON](execution-context.md)；只有调用方明确要求严格 JSON 时才只返回 JSON，否则可以附简短复制说明。

只有存在可用接口并满足宿主的明确用户授权要求时才派发。没有接口、安装或登录时遵循 [交接方式](browser-workflow.md)，提供完整可复制说明，标记“未派发”。不要把规划变成不断重新确认已经批准的任务。
