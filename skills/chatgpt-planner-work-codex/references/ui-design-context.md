# UI 约束

UI 规划可在普通 Chat 或 Work 完成。顺序依据：用户要求和实际读取的参考、已核实的项目设计系统与相邻页面、平台交互及可访问性约定。区分确认事实、推断和缺失信息；未能访问的 Figma 或截图不能声称已检查。

局部修正复用现有模式；新页面、流程或改版缺少完整设计时按 [自动设计](auto-ui-design.md) 提供有边界的方向。把布局、层级、关键交互、必要状态、响应式和可访问性要求放入 `implementation_constraints`，不额外发明品牌系统或页面。

Codex 根据真实环境选择组件和 CSS 等实现细节，在用户意图内运用当前适用的设计技能；重要设计冲突需报告。截图或渲染证据应注明页面、状态与视口，只收集验收需要的内容。没有实际视觉证据的部分标为未验证，不凭测试通过推断视觉通过。
