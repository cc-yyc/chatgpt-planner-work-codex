# 交接方式与可选浏览器

规划可在普通聊天或 Work 中完成；无需为了满足技能另外打开网页、切换模式或创建聊天。优先用当前已获授权且真实存在的宿主接口。浏览器只是在用户选择且工具可用时的一种途径。

交接前确认目的端、目标聊天/项目、当前请求和必要上下文。创建新聊天、向另一聊天发送消息、上传文件等动作须符合宿主的用户授权要求；技能被加载本身不是授权。不要猜测 API 或虚构派发回执。

无法自动交接时，在当前回复给出：

```text
交接状态：未派发，请复制到 Codex。
当前用户要求：实施以下已确认任务。
目标项目/目录：填写已知值；未知则让 Codex 先确认。
执行上下文：
（完整六字段 JSON）
请检查实际环境、按范围实施并运行验证，返回变更、命令结果和未验证项。
```

没有实际派发成功回执就不能写“已派发”；成功派发也不等于执行完成。已有回执而结果不明时先查状态，不能盲目重复发送。

需要用浏览器时，按可用浏览器工具和用户指定客户端操作，让用户自行完成登录。只传递必要上下文，不上传凭据、会话令牌或整个仓库。

Codex 发现真实环境与计划冲突时，可输出 `PLAN_CORRECTION`：原目标、已核实事实、冲突影响、建议纠正。规划端返回完整替换六字段；无法联系时明确需要的决定，继续不受影响的工作。结果反馈同样可以通过可复制复审包完成。
