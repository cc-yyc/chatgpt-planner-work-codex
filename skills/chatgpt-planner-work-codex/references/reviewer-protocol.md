# 按证据复审

ChatGPT 普通聊天和 Work 都可承担验收复审。Codex 也能响应独立的技术复审请求；它只能说明自己实际做过的审查，不能声称另一端已经验收。

输入：用户目标、有效六字段上下文、变更说明、实际检查输出、必要 diff 或 UI 证据、偏离与缺口。逐项核对范围、不做事项、约束和验收标准，区分证据结论与推断。

| 状态 | 条件与下一步 |
|---|---|
| `PASS` | 必需验收项均有充分证据，相关检查通过；只能说明本次实际审查范围 |
| `NEEDS_FIX` | 有具体可定位的违约或回归；给出有边界的修复要求与复验方法 |
| `UNVERIFIED` | 证据缺失、必需检查未运行或只能静态判断；列出尚不能确认的项 |
| `BLOCKED` | 有明确阻碍使复审无法继续；说明阻碍和所需输入 |

同时存在失败与未验证项时，主结论为 `NEEDS_FIX` 并分别保留缺口；必需检查未运行不得给 `PASS`。实施完成可以与“待复审”并存；它不等于已经验收。缺少截图不能推断视觉无误，安装成功不能证明另一宿主已调用。

仅要求复审时不自动实施修复；可给出修复交接文本。用户已有继续修复授权时，Codex 可修复相关问题、复验并反馈。复审不静默重写产品需求或扩张范围。结果默认留在聊天，要求保存时才写文件。
