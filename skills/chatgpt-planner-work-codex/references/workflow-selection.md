# 分析深度

| 模式 | 适用情况 | 行为 |
|---|---|---|
| `LITE` | 清楚、局部、可逆、可客观检查的小改动，无重要产品或架构选择 | 简短确认范围与验证即可 |
| `STANDARD` | 有边界的新功能、页面、接口或用户流程，需要方案和状态分析 | 分析依赖、边界与验收 |
| `COMPREHENSIVE` | 架构、核心流程、安全隐私权限、不可逆数据或重要发布 | 充分分析影响、回退和验证 |

模式改变分析深度，六字段交接不变。不能仅因 diff 小就把高风险操作视为 LITE，也不必为普通小修改强制另开规划会话。纯讨论不进入实施流程。

UI 局部修正优先 `REUSE_PATTERN`；有用户参考用 `REFERENCE_ADAPTATION`；新页面或新流程无完整参考时用 `AUTO_DESIGN` 并至少 STANDARD。具体规则见 [自动设计](auto-ui-design.md)。

若发现产品、数据、兼容性或范围的实质新问题，提升分析深度并纠正计划。普通技术细节由 Codex 判断。风险分类本身不创造额外审批要求，实际动作仍依据当前用户授权及宿主规则。
